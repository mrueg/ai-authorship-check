# AI Authorship Check

A GitHub Action that reads new issues, pull requests and comments and reacts with how it
thinks they were written:

| Reaction | Meaning | When |
|---|---|---|
| ❤️ | More likely written by a human | P(AI) < `human-threshold` (0.3) |
| 👀 | Undecided | in between |
| 🚀 | More likely AI-generated | P(AI) ≥ `ai-threshold` (0.8) |

The reactions are deliberately friendly: detection is a guess, and nobody should feel accused
by a bot. All three can be changed or turned off.

Classification runs **locally on the runner** with
[Vanguard](https://huggingface.co/ShantanuT01/vanguard-ai-text-detector), a ModernBERT-large
AI-text detector (MIT, 2nd place at PAN-CLEF 2026), exported to ONNX. No API key, no
external service, and comment text never leaves the runner.

## Usage

```yaml
# .github/workflows/ai-authorship-check.yml
name: AI Authorship Check
on:
  issues:              { types: [opened, edited] }
  issue_comment:       { types: [created, edited] }
  pull_request_target: { types: [opened, edited] }
  # pull_request_review_comment: { types: [created, edited] }   # read-only token on fork PRs, see below

permissions:
  issues: write
  pull-requests: write

# A newer event for the same text cancels the older run. An edit that doesn't touch the body
# (title, labels, base branch) gets its own group, so it can't cancel the run still judging
# the text; the job's `if` then skips it without pulling the image.
concurrency:
  group: ai-authorship-check-${{ github.event.action == 'edited' && !github.event.changes.body && format('edit-{0}', github.run_id) || github.event.comment.id || github.event.issue.number || github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  ai-authorship-check:
    if: github.event.action != 'edited' || github.event.changes.body
    runs-on: ubuntu-latest
    steps:
      - uses: mrueg/ai-authorship-check@v0.1.0
        with:
          dry-run: true   # watch the verdicts in the job summary first, then remove this
```

`pull_request_target` is used so PRs from forks get a token that can add reactions. This is
safe here because the action **never checks out or runs PR code** — it only reads the event
payload. Don't add a checkout step to this workflow.

Review comments (`pull_request_review_comment`) have no `_target` variant, so on PRs from
forks the token is read-only: the verdict still appears in the job summary and outputs, but
the reaction can't be added (a warning, or a failed job with `fail-on-error: true`).

The action runs as the container image `ghcr.io/mrueg/ai-authorship-check`. If you publish
your own copy to a private package, log in to GHCR before the action step and grant
`packages: read`, as [`.github/workflows/self-test.yml`](.github/workflows/self-test.yml) does.

## How it decides

```
event → skip? → AI signature? → clean up text → Vanguard → P(AI) → ❤️ / 👀 / 🚀
```

1. **Skip**: bots (`[bot]` logins, `type: Bot`), authors whose association is in
   `skip-associations` (owners and members by default), empty bodies, and edits that didn't
   change the body.
2. **Signature check**: explicit AI-tool markers give 🚀 without running the model: a
   `🤖 Generated with Claude Code` footer, a line that is only `Generated by GitHub Copilot`,
   a `Co-Authored-By:` trailer with an AI tool's address (`noreply@anthropic.com`, Copilot,
   Cursor, Devin, Jules), or pasted `As an AI language model …` boilerplate. HTML comments
   are searched, because tools hide markers there; quoted replies and code are not, so quoting
   someone else's AI text doesn't count. A tool name alone never counts: Claude, Devin and
   Jules are also people's names.
3. **Cleanup**: removes what the author didn't write or the model wasn't trained on: HTML
   comments (template instructions), fenced code, `<details>` logs, quoted replies, URLs and
   images, and lines that are template leftovers (section titles, checklists, empty
   issue-form fields, GitHub's stock placeholders like "A clear and concise description of…")
   or pasted stack frames and log lines. Texts shorter than `min-length` afterwards are
   skipped, and so is text that is clearly not English (`non-english`).
   Invisible characters (zero-width, soft hyphens, bidi controls) are removed before both the
   signature check and the model, so they can't hide a signature or nudge the score.
4. **Model**: P(AI) = sigmoid(logit) from Vanguard, reading up to `max-tokens` tokens. With
   `long-text: chunks`, longer texts are split into up to 4 chunks of `max-tokens` and P(AI)
   is their length-weighted mean.
5. **React**: ❤️ below `human-threshold`, 🚀 at or above `ai-threshold`, 👀 in between. On
   edits the action adds the new reaction, then removes its own other verdict reactions, so
   there is always exactly one. If an edit is skipped (say, cut below `min-length`), the old
   reaction and label are removed.

## Inputs

| Input | Default | |
|---|---|---|
| `human-threshold` | `0.3` | ❤️ when P(AI) is below this. |
| `ai-threshold` | `0.8` | 🚀 when P(AI) is at or above this; 👀 in between. Higher = fewer real people flagged. |
| `human-reaction` | `heart` | Any of `+1 -1 laugh confused heart hooray rocket eyes`, or `none`. |
| `undecided-reaction` | `eyes` | 〃 |
| `ai-reaction` | `rocket` | 〃 |
| `min-length` | `40` | Skip shorter texts (after cleanup). |
| `max-tokens` | `2048` | Tokens per model input. |
| `long-text` | `truncate` | `truncate` reads the first `max-tokens`; `chunks` scores up to 4 chunks and averages them. |
| `non-english` | `skip` | `skip` text that is clearly not English (mostly non-Latin script, or 20+ words with almost no English function words); `score` judges it anyway. |
| `skip-associations` | `OWNER,MEMBER` | Never judge these authors. |
| `signature-check` | `true` | 🚀 on explicit AI-tool signatures, without running the model. |
| `add-label` | `false` | Also label issues/PRs judged AI (removed if an edit flips it). |
| `label-name` | `possibly-ai-generated` | |
| `dry-run` | `false` | Classify and report, but don't react or label. |
| `fail-on-error` | `false` | Fail the job if a reaction or label can't be added. By default it's a warning: deleted comments, locked issues and read-only fork tokens are routine. |
| `github-token` | `${{ github.token }}` | Any token works; reactions are cleaned up under whichever account it belongs to. |

Outputs: `verdict` (`human` / `undecided` / `ai` / `skipped`), `p-ai`, `reason`. Each run also writes a
job summary.

## Limitations

AI-text detection is unreliable, and this action should start conversations, not end them.
Vanguard was not trained on GitHub text; short comments, non-native English, and AI drafts a
person edited are all hard cases. It was trained on English only, so other languages are
skipped by default; the check is a heuristic and lets mixed-language text through. The default thresholds give a wide 👀 band on purpose and
should be tuned on real data from your repos (see *Evaluating* below).

- **Signature matches are trusted.** A text with an AI-tool footer or trailer gets 🚀 whatever
  the rest of it says, including a person's own text with a pasted footer. Set
  `signature-check: false` to always use the model.
- **Every run downloads the image (about 1.7 GB) before it can decide anything**, including
  runs it then skips (bots, `skip-associations`, title-only edits). Expect about 1–1½ minutes
  of runner time per event. Filter events with a job-level `if:` to avoid paying for skips.
- **Not covered**: PR review summaries (`pull_request_review`), commit messages and
  Discussions.
- **Long texts**: by default only the first `max-tokens` tokens are read. `long-text: chunks`
  reads up to four times as much at up to four times the inference time; compare both with
  the Eval workflow's by-length table before switching.
- **GitHub App tokens**: when an edit gets no new reaction (skipped, or that verdict's
  reaction is `none`), old reactions are looked up under `github-actions[bot]` or the token's
  user, which misses an app's own reactions.

## Development

```sh
npm ci --ignore-scripts
npm run typecheck && npm test

# Full container test with a tiny random model (fast, no 1.6 GB download):
docker build --build-arg MODEL_TINY=true -t ai-authorship-check:smoke .
./scripts/smoke.sh ai-authorship-check:smoke
```

### The model

`model/export.py` downloads Vanguard at a pinned commit, exports it to ONNX and **fails the
build** if the ONNX model drifts from PyTorch by more than 1e-3. It then tries several int8
quantization settings and ships the first whose scores stay within 0.1 of PyTorch; if none
does, it ships fp32. For Vanguard none does (drift 0.33–0.55), so the image carries the
1.6 GB fp32 model. The Docker build runs the export; the result (with sha256, the chosen
setting and all check results in `/model/MODEL_INFO.json`) is baked into the image. Exporting
the real model needs about 8 GB of RAM, so it is built in CI.

To use a different single-logit classifier, build with
`--build-arg MODEL_REPO=… --build-arg MODEL_REVISION=<commit sha>`.

### Evaluating

```sh
# data.jsonl: {"text": "...", "label": "human" | "ai"} per line
docker run --rm -v "$PWD:/data" --entrypoint node ghcr.io/mrueg/ai-authorship-check:v0.1.0 \
  /app/dist/eval.js /data/data.jsonl
```

Or run the **Eval** workflow (Actions → Eval → Run workflow): it rebuilds the corpus from GH
Archive (see [`corpus/`](corpus/README.md)), builds the image with the real model and posts
the results to the job summary.

Prints AUROC, then for each `ai-threshold` the 🚀 precision/recall and the share of humans who
would get 🚀, and for each `human-threshold` the ❤️ precision/recall and the share of AI texts
that would get ❤️, followed by verdict shares per slice (origin, kind, length in tokens, …).
Pass `--long-text chunks` (or pick it in the workflow) to score long texts in chunks.

### Releasing

1. Run **Publish image** (Actions → Publish image → Run workflow) with version `vX.Y.Z`. It
   builds the image with the real model, pushes `ghcr.io/mrueg/ai-authorship-check:vX.Y.Z`,
   smoke-tests it and prints the `runs.image` line, pinned by digest, in the job summary. It
   refuses versions that already exist.
2. First release only: make the GHCR package public.
3. Put that line into `action.yml` in a pull request and merge it.
4. Tag the merge commit `vX.Y.Z` and push the tag. Tags don't trigger any build, so the
   image `action.yml` pins can't change underneath the release.
